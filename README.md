# 表情窝 · memenest

AstrBot 表情包插件：拾取群聊里的表情（或所有图片）→ 视觉模型打标 → 入库 → 聊天时按情绪摸一张、压缩后发出来。

支持多 BOT 共用一套库，表情可按人格与群/私聊限定范围，管理全部在 WebUI 的原生页面里完成。

---

## 一、它做什么

1. **收集**：监听所有会话的入站消息。默认只收平台判定为表情/贴纸的媒体；
   在「基础设置」里勾选「收全部图片」后，普通照片和截图也一起收。
2. **打标**：每条媒体调一次视觉模型，产出
   `{label, labels[], scenes[], text_in_image, caption}`。动图先抽 9 帧拼成一张静态图再送模型。
3. **入库**：文件落在插件数据目录，库容量可配，超限按「收藏/导入 → 用得少 → 最久未用 → 最早入库」淘汰。
4. **检索**：默认按关键词打分；开了「语义检索」后改用向量余弦相似度，命中率更高，失败自动回落关键词。
5. **发送**：机器人回复发出后，过几道闸决定要不要补一张表情，作为**独立消息**发出；
   发送前按配置压缩成表情包尺寸（静态图转 JPEG、动图转 GIF 降帧）。
6. **范围限定**：一条表情可以只给某几个人格用，也可以只在一个群/私聊里用；都满足才是通用的。
7. **管理**：`/memenest` 指令组 + WebUI 原生管理页，覆盖审核、分类、人格、拉黑、导入、向量索引。
8. **工具**：对 LLM 暴露 `memenest_search` / `memenest_send`，候选编号只在当回合有效。

代码按数据流分三层：`ingest/`（收集到入库）、`publish/`（检索到发送）、`store/`
（全部 SQL 集中在这里，其他层不直接碰数据库）。

## 二、安装

1. 把本目录放到 `AstrBot/data/plugins/memenest/`（目录名与 `metadata.yaml` 的 `name` 保持一致）。
2. 依赖：`Pillow`、`httpx`（AstrBot 运行环境通常已带）。
3. WebUI 里重载插件。首次启动会在 `data/plugin_data/memenest/` 建库。
4. 原生插件 API 挂在 `/memenest/...`，由宿主统一鉴权，管理页用 `bridge.apiGet/apiPost` 调。

库结构变更由插件自己按 `schema_version` 处理，不需要手工动数据库。

## 三、配置

配置在 WebUI 里按 5 组展示（顶层另有 `log_with_bot_id`）：

| 分组 | 项 |
|---|---|
| 顶层 `log_with_bot_id` | 日志区分机器人实例 |
| **基础设置** | 收集表情、收全部图片 |
| **收集与并发** | 判定方式（按概率 / 按冷却，跟着选择显示其中一项）、排队上限、并发数、单张体积上限、单张像素上限、收集黑名单 |
| **识别与入库** | 识别模型（下拉选已有提供商）、开启审核、存储上限 |
| **发表情** | 自动发表情、主动发送工具、发送概率、发送延迟、会话冷却、发送前压缩（长边与体积跟着显示）、发送白名单、人格隔离 |
| **语义索引** | 语义检索、向量模型提供商 ID、相似度下限 |

第一次用建议先看这三项：

- **识别模型**：不选也能跑，但只会入库、不打标；
- **开启审核**：默认开启，新表情先进待审核，满意了再点通过；
- **自动发表情**：默认开启，概率 0.25，觉得太频繁就调小。

## 四、指令

只保留「必须当场、在聊天里完成」的四个：

```
/memenest grab          引用一条带图的消息，把那张图收进来
/memenest on [分钟]     临时开启收集，不给分钟数就本次运行有效
/memenest off [分钟]    临时关闭收集，已排队的任务会跑完
/memenest status        看库存与运行状态
```

`grab` 收的是**被引用的那一张**，跳过判定与节流，并绑定当前人格——聊到一半看到好图，引用它发一句 `grab` 就行。

`on` / `off` 只改运行期状态，不动配置；给分钟数就到点自动恢复。本来就是这个状态时指令静默，不回消息。

其余操作都在管理页：审核、删除、拉黑、收藏、作用域、人格绑定、黑名单、容量、向量索引。
`on` / `off` / `grab` 需要管理员权限。

## 五、管理页

插件详情页里的「表情窝」，由宿主以受限 iframe 加载。

- **顶部**：总数 / 可用 / 待审核 / 禁用 / 黑名单 / 队列 / 向量覆盖率，一眼看运行状态；
  右侧是「全部审核 / 全部禁用 / 全部启用」，带数量且为 0 时置灰，作用于全库。
- **筛选**：状态、分类、人格、关键词（描述 / 图上文字 / 场景）、每页条数。
- **卡片**：缩略图、分类徽章、状态、人格标记、描述；单卡可收藏、切作用域、绑定人格、
  编辑描述与分类、拉黑、删除、切换状态。
- **批量栏**：选中后改主分类、拉黑、删除。
- **导入**：URL 与本地文件两种方式共用一组「人格 / 作用域 / 会话」参数；
  文件按张上传并显示「上传中 / 处理中」，URL 显示「下载中」。
- **黑名单**：分页查看并一键解禁（解禁后同图可重新入库）。

页面在 `allow-scripts` 但没有 `allow-same-origin` 的 iframe 里跑，直接 `fetch` 图片会被 CORS 拦，
所以缩略图一律走 `bridge.apiGet("thumb")` 取 base64 再塞进 `<img>`；页面不做任何直连请求。

## 六、检索是怎么做的

默认走关键词打分，开了语义检索后走向量，两条路的过滤条件完全一致。

1. **候选池缓存**：命中缓存的回合不再查库；任何写操作推进 `store.epoch`，缓存立刻作废，另有 30 秒兜底。
2. **过滤下推**：人格与状态在 SQL 层收敛，不把其他人格的表情读进内存。
3. **作用域内存收敛**：缓存的是「全库可用」池，会话作用域在内存里过滤，同一个池子服务所有会话。
4. **向量路径**：入库时把内容拆成「图上文字 / 画面描述 / 话题词」三路分别算向量存 `memo_embedding`，挑表情时各路单独打分再加权；
   相似度主导，收藏/近期/随机只在分差小于 0.1 时微调；向量索引按 `(model, dim)` 缓存，
   换模型或改维度会自动判定为缺向量并重算。

发送路径：`闸 → 缓存取池 → 内存过滤（作用域/人格/最近使用）→ 打分（关键词或向量）→ 压缩 → 发送`。

实测 492 条库、机器人 36 字回复下，top-1 命中率关键词 17% / 向量 40%；短句查询 43% / 77%。

## 七、数据与存储

- 库文件、图片、压缩缓存都在 `data/plugin_data/memenest/`，与插件代码分离。
- 库结构 **v1**：`memo` / `memo_label` / `memo_scene` / `memo_persona` / `memo_embedding` /
  `blocklist` / `meta`。`memo_embedding` 按 `(memo_id, kind, model)` 存，一条表情最多三行向量。
- 结构版本记在 `meta.schema_version`；和插件要求的不一致时启动直接报错并提示删库——
  这个插件还在 0.1.0 阶段，不做静默迁移，也没有需要兼容的旧结构。
- 写库失败会删掉临时文件，不留半行记录与孤儿文件；容量超限淘汰时同步删文件。

## 八、已知边界

- **管理页没有实时刷新**：改完数据要手动点「刷新」，走轮询而不是 SSE。
- **不做批量导出与拖拽排序**：需要导出直接读库。
- **只支持 QQ**：判定依赖 OneBot（aiocqhttp）的段信息与图床特征；平台没打表情标记、
  URL 也不像表情图床的图片，一律丢弃。
- **DNS 层面的 SSRF**：只校验字面 IP 与主机名黑名单，不做 DNS 解析后校验；重定向逐跳复检。
- **分类不可用**：模型未配置时收集照常工作，新条目只进待审核池，`label` 落到兜底分类。
- **人格解析**：读该会话命中 conf 的 `agent_runner.config.persona.persona_id`；对话级临时人格不参与判断。
- **作用域粒度是群/私聊**：不区分 BOT，同一个群换台 BOT 仍算同一个聊天。
- **向量检索依赖宿主的 embedding provider**：没配或调用失败时自动回落关键词，不会静默丢弃候选。

```powershell
$py = "C:\Users\Administrator\AppData\Local\AstrBot\backend\python\python.exe"

```

测试只覆盖插件自身逻辑，不导入宿主的 `astrbot.core`。每条保留的用例都在文件头注明了
