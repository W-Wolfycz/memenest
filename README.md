# 表情窝 · memenest

AstrBot 表情包插件：拾取群聊里的表情（或所有图片）→ 视觉模型打标 → 入库 → 聊天时按情绪摸一张、压缩后发出来。

支持多 BOT 共用一套库，表情可按人格与群/私聊限定范围，管理全部在 WebUI 的原生页面里完成。

---

## 一、它做什么

1. **收集**：监听所有会话的入站消息。默认只收平台判定为表情/贴纸的媒体；
   在「基础设置」里勾选「收全部图片」后，普通照片和截图也一起收。
2. **打标**：每条媒体调一次视觉模型，产出
   `{label, labels[], scenes[], text_in_image, caption}`。动图先抽 9 帧拼成一张静态图再送模型。
3. **入库**：文件落在插件数据目录，库容量可配，超限按「收藏/导入 → 用得少 → 最久未用 → 最早入库」淘汰。
4. **检索**：默认按关键词打分；开了「语义检索」后改用向量余弦相似度，命中率更高，失败自动回落关键词。
5. **发送**：机器人回复发出后，过几道闸决定要不要补一张表情，作为**独立消息**发出；
   发送前按配置压缩成表情包尺寸（静态图转 JPEG、动图转 GIF 降帧）。
6. **范围限定**：一条表情可以只给某几个人格用，也可以只在一个群/私聊里用；都满足才是通用的。
   另有一份**禁用人格名单**：命中的「表情 + 人格」直接不发送，优先级高于可用名单（写着通用也挡得住）。
7. **管理**：`/memenest` 指令组 + WebUI 原生管理页，覆盖审核、分类、人格、拉黑、导入、向量索引。
8. **工具**：对 LLM 暴露 `memenest_search` / `memenest_send`，候选编号只在当回合有效。

代码按数据流分三层：`ingest/`（收集到入库）、`publish/`（检索到发送）、`store/`
（全部 SQL 集中在这里，其他层不直接碰数据库）。

## 二、安装

1. 把本目录放到 `AstrBot/data/plugins/memenest/`（目录名与 `metadata.yaml` 的 `name` 保持一致）。
2. 依赖：`Pillow`、`httpx`（AstrBot 运行环境通常已带）。
3. WebUI 里重载插件。首次启动会在 `data/plugin_data/memenest/` 建库。
4. 原生插件 API 挂在 `/memenest/...`，由宿主统一鉴权，管理页用 `bridge.apiGet/apiPost` 调。

库结构变更由插件自己按 `schema_version` 处理，不需要手工动数据库。

## 三、配置

配置在 WebUI 里按 5 组展示（顶层另有 `log_with_bot_id`）：

| 分组 | 项 |
|---|---|
| 顶层 `log_with_bot_id` | 日志区分机器人实例 |
| **基础设置** | 收集表情、收全部图片 |
| **收集与并发** | 判定方式（按概率 / 按冷却，跟着选择显示其中一项）、排队上限、并发数、单张体积上限、单张像素上限、收集黑名单 |
| **识别与入库** | 识别模型（下拉选已有提供商）、开启审核、存储上限、待审核池上限、每日识图预算 |
| **发表情** | 自动发表情、主动发送工具、发送概率、发送延迟、会话冷却、发送前压缩（长边与体积跟着显示）、发送白名单、人格隔离 |
| **语义索引** | 语义检索、向量模型提供商 ID、标签来源、关键词兜底最低分、语义相似度下限、选图变化程度 |

第一次用建议先看这三项：

- **识别模型**：不选也能跑，但只会入库、不打标；
- **开启审核**：默认开启，新表情先进待审核，满意了再点通过；
- **自动发表情**：默认开启，概率 0.25，觉得太频繁就调小。

## 四、指令

只保留「必须当场、在聊天里完成」的几个：

```
/memenest status        看库存与运行状态
/memenest help          显示这份说明
/memenest grab          引用一条带图的消息，把那张图收进来
/memenest mute          把表情和这条指令一起发（或引用一张），对当前人格禁用这张
/memenest unmute        同上，恢复它在当前人格下的可用
/memenest on [分钟]     临时开启收集，不给分钟数就本次运行有效
/memenest off [分钟]    临时关闭收集，已排队的任务会跑完
```

`grab` 收的是**被引用的那一张**，跳过判定与节流，并绑定当前人格——聊到一半看到好图，引用它发一句 `grab` 就行。

`mute` / `unmute` 认的是**图本身**：先把图抓下来算指纹，再回库里找对应那条（发出去的是压缩图，字节和原图不同，
所以先比 SHA-256，再比感知指纹，后者实测只差 0–3 bit）。命中的是「这张表情 + 当前会话解析到的人格」这个组合，
**不改可用名单**——所以通用表情禁掉一个人格后，其余人格（包括以后新增的）照样能用。

`on` / `off` 只改运行期状态，不动配置；给分钟数就到点自动恢复。本来就是这个状态时指令静默，不回消息。

其余操作都在管理页：审核、删除、拉黑、收藏、作用域、人格绑定与禁用人格、黑名单、容量、向量索引。
**全部指令都需要管理员权限**，且是**用装饰器声明**的
（`@filter.permission_type(PermissionType.ADMIN)`）——Dashboard 指令管理页显示的就是这个值；
`verify_deploy` 会核对「注册到的每条指令都声明了 ADMIN」，改名或新增指令忘了声明会直接失败。
改权限请改装饰器，不要在函数体里判 `is_admin()`（那样页面会一直显示 everyone）。

这些子命令通过宿主的指令组（`@filter.command_group("memenest")`）注册，因此会出现在 WebUI 的指令列表和 `/help` 里；
只发一个 `/memenest`（不带子命令）等同于 `status`。不带唤醒前缀的 `memenest status` 由插件的消息钩子兜底。

## 五、页面

插件详情页里只有一个页面「表情窝」，顶部三个标签切换：大盘 / 表情管理 / 发送历史。

### 大盘（默认）

一屏看完运行状态，并把需要动手的问题直接列出来：

- **库**：总数 / 可用 / 待审 / 禁用 / 黑名单 / 无描述，以及容量条（接近上限变红）。
- **识图**：模型是否可用、今日识图预算、因缺模型入库的条数。
- **检索**：语义检索是否启用、向量覆盖率、当前模型；可直接「补齐向量」。
- **存储**：数据库 / WAL / blobs / inbox / cache / imports / tmp 实际占用，
  以及缺失文件与孤儿文件数。
- **发送**：尝试 / 已发 / 失败 / 取消，加拒发原因分布。
- **处置**：重新识图（无描述）、完整性体检、整理数据库（VACUUM）、清理孤儿文件。
- **告警**：模型不可用、预算用尽、无描述条目、缺模型入库、文件缺失、孤儿文件、
  容量接近上限、向量未补齐，都会挂成红/黄条——不用进管理视图翻。
- 卡片不给底色、不描边，只靠一层很淡的投影分出边界；标签页是方角按钮（圆角 6px），
  用投影区分「可点」与「已选中」；「处置」只放按钮，说明挂在 `title` 上。
- 「最近发送」只显示最近 5 条，右下角「查看全部 →」跳到发送历史标签。

### 发送历史

持久化的发送记录（`send_log` 表），回答「上周那张到底发出去没有 / 走的哪条路」：

- 每行：时间、检索路（向量 / 关键词 / 工具）、分类、会话、触发文本；
  失败、取消、文件缺失也会记，失败行用红色徽标并**带原因**（`失败 · TimeoutError`、
  `文件缺失 · file_missing`、`platform_unavailable` 等），不用再翻日志对时间。
- 筛选：按检索路、按触发文本或分类搜索；每页 20 / 50 条可切。
- 保留窗口：**最近 90 天 / 最多 20000 条**，先到先裁（写入时顺手清理）。
  刻意不做配置项——多数人答不出该留多少条，多一个键就多一份文档与排查面。
- 被拦下的原因（掷骰子没过、冷却、不够相关）不进这张表，仍在大盘看聚合分布：
  「没发生的事」逐条存只会淹没有用信息。

### 表情管理

浏览、审核、编辑与导入：

- **顶部**：总数 / 可用 / 待审核 / 禁用 / 黑名单 / 队列 / 向量覆盖率 / 识图预算（开了才显示），
  一眼看运行状态；右侧是「全部审核 / 全部禁用 / 全部启用」，带数量且为 0 时置灰，作用于全库。
  「补齐」会同时补两样东西：缺向量的算向量，缺感知指纹的读文件补指纹（动图补三帧复合）。
- **试一试**：输入一句话（可带用户消息），看关键词路 / 向量路各自的 top 候选与原始分。
  与真实挑图共用同一套打分口径（含同类避让、标点先验），只差最后的多样性重排；
  调提示词、权重、阈值前后各跑一遍同一句话对比变化，不过闸、不记用量。
- **备份**：一键把数据库快照与 blobs/inbox 打包成 zip 存到数据目录 `exports/`，
  保留最近 3 份；页面提供列表与删除，文件请到该目录取走（不做 HTTP 大文件下载）。
- **筛选**：状态、分类、人格、关键词（描述 / 图上文字 / 场景）、每页条数。
- **卡片**：缩略图、分类徽章、状态、人格标记、描述；单卡可收藏、切作用域、绑定人格、
  编辑描述与分类、拉黑、删除、切换状态。
- **批量栏**：选中后改主分类、导出、拉黑、删除。
- **导出**：勾选条目点「导出」，把图片打成一个 zip 下载，文件名是毫秒级时间戳
  （`2001-02-03T04_05_06_007.zip`，冒号换成下划线）；文件已丢失的条目跳过并提示。
- **导入**：URL、本地文件、清单 URL 三种方式共用一组「人格 / 作用域 / 会话」参数；
  文件按张上传并显示「上传中 / 处理中」，URL 显示「下载中」。
  清单是一份 JSON（`[url, ...]` 或 `{"items": [url | {"url": ...}]}`，最多 200 条），一次整批入队。
- **黑名单**：分页查看并一键解禁（解禁后同图可重新入库）。

页面在 `allow-scripts` 但没有 `allow-same-origin` 的 iframe 里跑，直接 `fetch` 图片会被 CORS 拦，
所以缩略图一律走 `bridge.apiGet("thumb")` 取 base64 再塞进 `<img>`；页面不做任何直连请求。

## 六、检索是怎么做的

默认走关键词打分，开了语义检索后走向量，两条路的过滤条件完全一致。

1. **候选池缓存**：命中缓存的回合不再查库；任何写操作推进 `store.epoch`，缓存立刻作废，另有 30 秒兜底。
2. **过滤下推**：人格与状态在 SQL 层收敛，不把其他人格的表情读进内存。
3. **作用域内存收敛**：缓存的是「全库可用」池，会话作用域在内存里过滤，同一个池子服务所有会话。
4. **向量路径**：入库时把内容拆成「图上文字 / 画面描述 / 话题词」三路分别算向量存 `memo_embedding`，挑表情时各路单独打分再加权；
   相似度主导，收藏/近期/随机只在分差小于 0.1 时微调；向量索引按 `(model, dim)` 缓存，
   换模型或改维度会自动判定为缺向量并重算。最高分低于「语义相似度下限」时这回合不发（默认 0 = 不设限）。
5. **同类避让**：除全局「最近用过」外，每个分类另记最近 4 张，打分时只压同类——连续两句同情绪的话不会一直抽到同一张。
6. **标点先验**：从回复的问号/感叹号/省略号/波浪号猜语气（`puzzle` / `wow` / `cheer` / `blank` /
   `slack` / `shy` / `love`），只加很小的一点分，补关键词与向量都读不出情绪的情况。

发送路径：`闸 → 缓存取池 → 内存过滤（作用域/人格/最近使用）→ 打分（关键词或向量）→ 压缩 → 发送`。
发送延迟按配置值抖动（×0.75~1.25）再加文本长度因子——固定秒数在群里看久了会被认出来；配 0 保持立即发。

实测 492 条库、机器人 36 字回复下，top-1 命中率关键词 17% / 向量 40%；短句查询 43% / 77%。

## 七、数据与存储

- 库文件、图片、压缩缓存都在 `data/plugin_data/memenest/`，与插件代码分离；备份 zip 在其 `exports/` 下。
- 去重两级：SHA-256 字节哈希 + 感知指纹。**动图用三帧复合指纹**（首/中/尾各一帧，":" 连接，
  三帧都在阈值内才判重），只比首帧会把「首帧相同、后续不同」的动画判成同一张。
- 库结构 **v2**：`memo` / `memo_label` / `memo_scene` / `memo_persona` / `memo_persona_block` /
  `memo_embedding` / `blocklist` / `meta`。`memo_embedding` 按 `(memo_id, kind, model)` 存，一条表情最多三行向量。
- `memo_persona` 是可用名单（`*` = 通用），`memo_persona_block` 是禁用人格名单；判定时禁用优先。
- **老库原地升级**：`meta.schema_version` 更小时逐级补结构（只加表/列，不动已有数据），不要求删库；
  只有「库结构比插件新」才拒绝启动——降级跑未知结构会写坏库。
- 写库失败会删掉临时文件，不留半行记录与孤儿文件；容量超限淘汰时同步删文件。

## 八、已知边界

- **管理页没有实时刷新**：改完数据要手动点「刷新」，走轮询而不是 SSE。
- **不做批量导出与拖拽排序**：需要导出直接读库。
- **只支持 QQ**：判定依赖 OneBot（aiocqhttp）的段信息与图床特征；平台没打表情标记、
  URL 也不像表情图床的图片，一律丢弃。
- **DNS 层面的 SSRF**：只校验字面 IP 与主机名黑名单，不做 DNS 解析后校验；重定向逐跳复检。
- **分类不可用**：模型未配置时收集照常工作，新条目只进待审核池，`label` 落到兜底分类。
  这类退化会在面板计数里显示「缺模型」，并在日志里记一条 WARNING；宿主冷启动时插件可能
  先于 provider 加载完成，这时会自动重试解析（间隔 60 秒），模型就绪后识图即刻恢复。
- **识图失败会重试一次**：单张图最多 2 次尝试（间隔 1.2s），每次尝试都计一次识图预算；
  两次都失败就按「这张没入库」处理（日志里是 INFO 的 `分类失败 reason=...`）。
- **重新识图与体检都不改审核状态**：重新识图只更新描述/标签/场景，不把条目从待审核移出去；
  体检只读，清孤儿只删「没有任何记录引用」的文件。两者的进度只存在内存里，重载后清零。
- **启动时读取的配置**：识别模型与「主动发送工具」开关在插件启动时解析一次，改了要在 WebUI 里重载插件才生效；其余开关每条消息现读。
  视觉模型 ID 例外：取不到时按需重试，provider 后加载完成也能自动接上。
- **人格解析**：读该会话命中 conf 的 `agent_runner.config.persona.persona_id`；对话级临时人格不参与判断。
  `mute` / `unmute` 也按这个结果落库——解析不到人格时指令直接拒绝，不会退化成「对所有人格生效」。
- **作用域粒度是群/私聊**：不区分 BOT，同一个群换台 BOT 仍算同一个聊天。
- **向量检索依赖宿主的 embedding provider**：没配或调用失败时自动回落关键词，不会静默丢弃候选。

## 九、测试

```powershell
$py = "C:\Users\Administrator\AppData\Local\AstrBot\backend\python\python.exe"
& $py -m pytest memenest\tests -q              # 在 D:\AI\dsh\plugin 下执行
& $py memenest\scripts\verify_mutations.py     # 变异验证：25 条，全部要拦住
& $py memenest\scripts\verify_deploy.py        # 部署前自检：schema/入口/star_map/页面
& $py memenest\scripts\verify_all.py           # 全量：编译/契约/路由/端到端
```

测试只覆盖插件自身逻辑，不导入宿主的 `astrbot.core`。每条保留的用例都在文件头注明了
它守的是哪种静默失效；`verify_all.py` 额外检查前后端契约——路由漏注册、前端调空接口、
参数名不匹配这类"跑起来才炸"的问题都在那里拦。
